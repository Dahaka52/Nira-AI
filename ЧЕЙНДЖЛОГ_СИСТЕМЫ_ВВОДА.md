# Обновление системы ввода (Barge-in Rework & Multi-user)

Этот документ описывает все функции и изменения, внедренные в систему ввода, агрегации контекста и мультиплеера.

## 1. Умная буферизация STT
- **Контекстный таймер:** Внедрен настраиваемый таймер сбора речи `stt_buffer_timeout_ms` (по умолчанию 800мс). Теперь Нира не перебивает после первого же распознанного слова или короткой паузы, а ждет заданное время перед отправкой реплики в LLM.
- **Фильтрация бэкченнелов:** Если в собранном буфере оказались только короткие слова-поддакивания (например, "угу", "ага", "ясно"), они добавляются в контекст истории, но задача на ответ не формируется. Это позволяет пользователю поддакивать Нире, не сбивая её с мысли.

## 2. Мягкие прерывания и Режим Слушателя
- **Отказ от тотального хард-прерывания:** Ранее любой звук из микрофона прерывал генерацию ответа. Теперь мгновенная остановка LLM (barge-in) происходит ТОЛЬКО при произнесении стоп-слов из настроек `stt_stop_words` ("стоп", "подожди", "хватит").
- **Режим Слушателя:** Внедрено состояние `is_listening`. Если пользователь произносит триггеры вроде "послушай" или "хочу рассказать" (список `stt_listen_triggers`), Нира переходит в режим активного слушателя. Она продолжает собирать все фразы и записывать их в память, но **не отвечает**, пока пользователь не скажет освобождающую фразу из списка `stt_release_triggers` (например, "что скажешь", "я всё").

## 3. LLM-Фильтрация мусора STT
- **Опциональный суммаризатор:** В `config.yaml` добавлен параметр `stt_filter_mode`. При значении `"llm"` ядро `JAIson` вызывает легкую текстовую генерацию перед добавлением фразы в контекст.
- **Очистка шума:** Скрытый системный промпт просит LLM убрать "мусорные" слова, исправить опечатки распознавания, а в случае если фраза состоит исключительно из бессмысленного шума — вернуть команду `DROP`, после которой фраза тихо удаляется из конвейера.

## 4. Динамические Сцены
- **Автопереключение контекста:** При переключении режима вывода аудио (Local / Discord), система автоматически меняет значение `active_scene`.
- **Динамические файлы промптов:** Промптер обучен автоматически искать файл сцены по шаблону `scene_{active_scene}.md`. 
  - Создан файл `prompts/scenes/scene_local.md` для приватного общения у компьютера.
  - Создан файл `prompts/scenes/scene_discord.md` для многопользовательского режима на сервере.
  - Их контекст автоматически подтягивается и отдается LLM в зависимости от активного режима.

## 5. Мультиплеер и Распознавание собеседников
- **Контекст сцены в истории:** Реплики пользователей теперь записываются в историю в формате `[Local] Имя:` или `[Discord] Имя:`, чтобы LLM всегда понимала, кто и откуда с ней говорит.
- **Динамический список пользователей (Hot-reload):** Создан файл `configs/known_users.json`. Добавление связок `"id_или_ник_дискорда": "Имя"` применяется мгновенно при следующей же реплике, без необходимости перезагрузки пайплайна.
- **Интеграция с Discord-никами:** Если имя пользователя не задано ни в `config.yaml`, ни в `known_users.json`, система обращается к нему по сырому `speaker_id`. В случае с Discord мостом `speaker_id` по умолчанию является никнеймом, что закрывает потребность в автоматическом обращении по нику из Дискорда.
